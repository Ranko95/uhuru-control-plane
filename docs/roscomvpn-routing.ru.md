# RoscomVPN DEFAULT: CDN и приёмка

Control Plane добавляет `Routing: happ://routing/onadd/<base64 compact JSON>` и
`Profile-Update-Interval: 1` только после успешного получения конфигураций и COMMIT.
VLESS-тело сохраняется. Все Ссылки подписки получают один профиль `Uhuru DEFAULT`;
распознавания приложения и выключателя нет. `DeliveryController` статически
импортирует JSON и собирает заголовок в `getConfigurations`. Из upstream меняется
только имя; правила, DNS, `LastUpdated` и URL геобаз сохраняются.

По уточнению Пользователя 6 октября 2026 года геобазы пока скачиваются клиентами
напрямую с исходного CDN `cdn.jsdelivr.net`. Размещать базы на VPS и добавлять
`/routing/` в nginx не требуется. Control Plane не скачивает геобазы при запросе
подписки; клиенту нужен доступ к CDN для загрузки файлов.

Формат описан в документации [Happ](https://www.happ.su/main/dev-docs/routing) и
[Incy](https://docs.incy.cc/en/routing/). Совместимость установленных сборок
подтверждается отдельно на телефонах.

## Деплой и клиентская приёмка

Достаточно штатного деплоя приложения: tracked JSON попадает в релиз вместе с кодом.
Проверить действующую Ссылку подписки через реальный nginx: ответ 200, прежнее
VLESS-тело, `Profile-Update-Interval: 1`, декодируемый `Routing` с `Uhuru DEFAULT`
и исходными CDN URL из JSON. Секретный URL и тело не публиковать в журнале проверок.
Ответы 403/404/410/503 не должны содержать оба новых заголовка.
Проверка публичной выдачи подписки на VPS пока **NOT RUN**.

Для каждой строки записать версии приложения и ОС, затем импортировать **одну и ту же**
HTTPS-Ссылку подписки и подтвердить:

- Подключения добавились; `Uhuru DEFAULT` активен; обе геобазы загрузились с CDN.
  Проверить загрузку в используемой сети телефона: проверка CDN из среды разработки
  не подтверждает его доступность на телефоне.
- REALITY/Vision подключается. После reconnect работают direct, proxy и block.
  Сохранить выбранные доменные и IP-примеры и подтвердить маршруты эффективной
  конфигурацией или журналом клиента. Проверить DNS и порядок пересекающихся правил
  `block-proxy-direct`; отдельное открытие сайта не доказывает маршрут.
- Проверить фактическое распознавание `UseChunkFiles: "true"` и `RouteOrder`.
- Выбрать другой профиль вручную и выполнить refresh: DEFAULT снова активен,
  дубликата профиля нет.

## Ручное обновление

Закрепить новый upstream SHA и версии геобаз, проверить скачивание именно указанных
CDN-файлов и их опубликованные SHA-256. Затем заменить JSON и ожидаемый профиль
в delivery-тесте. `LastUpdated` должен быть строго больше предыдущего, в том числе
при возврате старых правил. Правила и DNS не переписывать. Клиент получает изменение
при refresh; применение проверять после reconnect.

Интервал 24 рекомендует refresh подписки и не обновляет наш upstream-снимок.
Автоматического updater, контроля свежести и собственного зеркала нет.
